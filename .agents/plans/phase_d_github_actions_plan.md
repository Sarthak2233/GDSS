# Implementation Plan - Phase D: GitHub Actions Automated PR Collision Audit (`phase-d-github-actions`)

## 1. Goal Description
Implement the automated GitHub Actions PR Collision Radar delivery interface (**Phase 1.8b**).
When a developer opens or pushes to a pull request, GDSS executes in GitHub CI, evaluates the incoming branch against **all other concurrently open PRs** across the repository, builds the interaction tensor matrix ($\Omega_{ij}$), and posts/updates a single **sticky Markdown collision radar report** using the native repository `GITHUB_TOKEN`.

---

## 2. Key Architecture & Design Decisions

### A. The "Sticky Comment" Pattern
Instead of spamming the PR with a new comment on every push:
1. Every comment generated by GDSS starts with a hidden HTML signature:
   `<!-- GDSS_PR_RADAR_SIGNATURE -->`
2. On every PR push, GDSS queries existing issue comments via `GET /repos/{owner}/{repo}/issues/{pr_number}/comments`.
3. If an existing comment containing the signature is found:
   `PATCH /repos/{owner}/{repo}/issues/comments/{comment_id}` (updates in-place).
4. If no existing comment is found:
   `POST /repos/{owner}/{repo}/issues/{pr_number}/comments` (creates a clean top-level summary).

### B. Sticky Comment Anatomy & Experience
```markdown
<!-- GDSS_PR_RADAR_SIGNATURE -->
## 🛰️ GDSS PR Collision Radar

| Status | Target | Colliding PR | Overlapping Symbol | Risk ($\Omega_{ij}$) |
| :---: | :--- | :--- | :--- | :---: |
| ⚠️ | `services/auth.py` | #41 by @alice (`feature-auth`) | `login()` signature | **0.85 (High)** |

### ⚠️ Semantic Collision Topology
- **PR #42** (this PR) calls `services/auth.py::login(user)` in `services/billing.py`.
- **PR #41** modifies `login(user)` to `login(user, timeout=30)` in `services/auth.py`.
- **Merge Order Recommendation:** Merge **PR #41 first**, then rebase/adapt PR #42.

### 🛡️ Verified Convergence Suggestion
Tested inside ephemeral sandbox worktree (syntax: OK, types: OK):
```suggestion
def login(user: str, timeout: int = 30) -> bool:
```
*Click **"Commit suggestion"** above to apply the verified reconciliation.*
```

### C. Blocking vs. Informational Mode
Maintainers can configure blocking behavior in `.gdss.yml`:
```yaml
radar:
  fail_on_collision: false    # If true, exits with code 1 when Omega_ij >= threshold
  risk_threshold: 0.8         # Minimum collision risk score to flag as high risk
```
- By default, `fail_on_collision: false` (informational radar mode: alerts authors and reviewers without blocking unrelated CI checks).
- When `fail_on_collision: true`, any collision exceeding `risk_threshold` exits non-zero, turning the CI check red.

### D. Security & Permissions
- Uses standard GitHub Action permissions:
  ```yaml
  permissions:
    contents: read
    pull-requests: write
    issues: write
  ```
- Works for forks in read-only / check-run mode.
- Does not require any external third-party API keys. Uses `GITHUB_TOKEN` for GitHub API and GitHub Models / Copilot.

### E. How Patch Generation Happens via GITHUB_TOKEN & GitHub Models / Copilot

When a cross-PR collision is detected, candidate reconciliation patches are generated and validated through a 5-step pipeline:

```
[1. GITHUB_TOKEN Detected in Runner]
       │
       ▼
[2. GitHub Models Endpoint (`https://models.inference.ai.azure.com`)]
   - Authenticates directly using Authorization: Bearer ${{ secrets.GITHUB_TOKEN }}
   - Selects model: gpt-4o / gpt-4o-mini (or GITHUB_MODEL from .gdss.yml)
   - Zero external API keys, zero token fees to GDSS
       │
       ▼
[3. AST Prompt Construction (`gdss/ai/prompt_builder.py`)]
   - Feeds minimal, focused AST context:
     * Colliding function/class signatures from both branches
     * Downstream call sites and type definitions
       │
       ▼
[4. Ephemeral Worktree Sandbox Test (`gdss/validation/sandbox.py`)]
   - Tests Copilot's draft inside isolated /tmp/gdss-sandbox-...
   - AST syntax check (syntax.py)
   - Static typecheck (mypy / tsc)
   - Targeted unit tests (pytest / pnpm test)
       │
       ├─────────────────────────────────┐
       ▼                                 ▼
   [PASSED]                           [FAILED]
[5. Native GitHub Suggestion]       [Discard Patch]
   Posts ```suggestion``` block        Posts collision radar table &
   with 1-click commit button          risk explanation only (no broken code)
```

- **Graceful Model-Free Fallback:** If the repository has GitHub Models disabled or if the PR comes from an external fork, GDSS falls back to deterministic AST merge strategies (`keep_left`, `keep_right`) or informational radar diagnostics. The action **never fails** due to AI provider unavailability.

## 3. Proposed Changes

Grouped by component:

### Core CI Module: `gdss/validation/` (Layer 10)
#### [NEW] `gdss/validation/pr_audit.py`
- `PRAuditContext`: Dataclass holding repo owner, repo name, current PR number, base branch, head branch, commit SHA, and GitHub token.
- `parse_github_env()`: Reads GitHub Actions environment variables (`GITHUB_REPOSITORY`, `GITHUB_EVENT_PATH`, `GITHUB_TOKEN`, `GITHUB_REF`, `GITHUB_BASE_REF`).
- `fetch_concurrent_prs()`: Queries GitHub REST API (`/repos/{owner}/{repo}/pulls?state=open`) to retrieve all other open PRs.
- `audit_pr_collisions()`: Fetches branch refs, extracts semantic operators, and executes `TensorEngine` to compute $\Omega_{ij}$ between current PR and concurrent PRs.
- `render_radar_markdown()`: Renders the structured markdown radar table, topology explanations, and suggestion blocks.
- `post_or_update_sticky_comment()`: Finds existing comment with signature or posts new comment via GitHub API.

---

### CLI Interface: `gdss/cli/`
#### [MODIFY] `gdss/cli/main.py`
Add `gdss audit-pr` sub-command:
```bash
gdss audit-pr [--repo <PATH>] [--token <GITHUB_TOKEN>] [--pr-number <N>] [--dry-run] [--output <FILE>]
```
- When run inside GitHub Actions: automatically detects PR context from environment.
- When run locally or in tests: `--dry-run` prints the formatted markdown report to stdout without calling GitHub API.

### Tests: `tests/validation/`
#### [NEW] `tests/validation/test_pr_audit.py`
TDD suite testing:
1. `test_parse_github_env_from_event_json`: Correctly parses PR metadata from GitHub Actions event payload.
2. `test_fetch_concurrent_prs_filters_self`: Excludes the current PR from the concurrent branch list.
3. `test_render_radar_markdown_no_collision`: Generates clean "All clear / minimal merge risk" report when $\Omega_{ij} \approx 0$.
4. `test_render_radar_markdown_with_collision`: Generates collision table, @mentions, symbol names, and risk badges when $\Omega_{ij} \ge \text{threshold}$.
5. `test_sticky_comment_create_vs_patch`: Verifies that an existing comment is patched in-place rather than creating duplicate comments.
6. `test_cli_audit_pr_dry_run`: Executes `gdss audit-pr --dry-run` and asserts markdown output.
7. `test_threshold_exit_code`: Verifies that `fail_on_collision` triggers non-zero exit when risk exceeds threshold.
